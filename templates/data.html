Methodology

  1. Ingestion. Rows are read from the CSV in the column order shown above. Exact duplicates (same state, district, disease, month and cases) are removed once; rows missing a state or district are dropped.
  2. Aggregation. Cases are summed per state and per district, and each state's disease list is derived from its rows. State totals are sorted A–Z, districts and diseases by cases descending.
  3. Modelled legacy rows. COVID-19, Influenza and Tuberculosis are absent from the sample file. Each is reconstructed per state as a fixed share of that state's CSV total (14% / 9% / 6%) scaled by a deterministic factor of 0.75–1.25 derived from a hash of the state and disease name, so values vary between states instead of being copy-pasted. Every such figure is badged est everywhere it appears.
  4. Monthly series. The date column builds the time series used by Analytics, Seasonal and Alerts. Modelled totals are spread across the months using that state's own reported shape, with a largest-remainder split so the months sum exactly to the modelled total.
  5. Population normalisation. Cases per lakh = cases ÷ population × 100,000. Population is public reference data used only for ranking and normalisation; raw counts are never restated.
  6. Coverage. District coverage = districts present in the dataset ÷ approximate district total, explaining why one state reports many more districts than another.
  7. Shading. Map and table buckets split the range into five equal-width steps up to the current maximum for the selected metric (reported cases or cases per lakh).
  8. Provenance rules. The reporting period comes from the data itself (the month range of the CSV, or the year of a real IDSP file). When a file carries no period, none is claimed — file modification times are shown only labelled as file timestamps.
